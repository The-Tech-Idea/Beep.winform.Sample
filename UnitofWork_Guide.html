Overview

The UnitofWork<T> class is a comprehensive implementation of the Unit of Work pattern for managing entities of type T. It provides change tracking, transaction management, CRUD operations, and event-driven data manipulation capabilities.

?? Unit of Work Pattern

This class maintains a list of objects affected by a business transaction and coordinates writing out changes and resolving concurrency problems. It tracks entity states (Added, Modified, Deleted) and provides commit/rollback functionality.

Events & Triggers

The UnitofWork provides a comprehensive event system for intercepting and controlling data operations:

CRUD Events

PreInsert / PostInsert

Fired before and after record insertion

PreUpdate / PostUpdate

Fired before and after record updates

PreDelete / PostDelete

Fired before and after record deletion

PreQuery / PostQuery

Fired before and after query execution

Lifecycle Events

PreCreate / PostCreate

Fired when creating new entities

PostEdit

Fired when entity properties are modified

PreCommit / PostCommit

Fired during transaction commit operations

?? Event Flow Example

Insert Operation: PreCreate ? PostCreate ? PreInsert ? PostInsert ? PreCommit ? PostCommit

Update Operation: PostEdit ? PreUpdate ? PostUpdate ? PreCommit ? PostCommit

Delete Operation: PreDelete ? PostDelete ? PreCommit ? PostCommit

Usage Examples

Basic CRUD with Data Source

// Initialize unit of work with data source var unitOfWork = new UnitofWork<Customer>(dmeEditor, "NorthwindDB", "Customers"); // Load all customers var customers = await unitOfWork.Get(); // Create new customer unitOfWork.New(); var newCustomer = unitOfWork.CurrentItem; newCustomer.CustomerName = "New Company"; newCustomer.Country = "USA"; // Update existing customer var existingCustomer = unitOfWork.Read("ALFKI"); existingCustomer.ContactName = "Updated Contact"; unitOfWork.Update(existingCustomer); // Commit all changes var result = await unitOfWork.Commit(); if (result.Flag == Errors.Ok) { Console.WriteLine("All changes saved successfully"); }

List Mode Operations

// Create unit of work in list mode var existingData = new ObservableBindingList<Customer>(customerList); var unitOfWork = new UnitofWork<Customer>(dmeEditor, true, existingData); // Work with in-memory data unitOfWork.Add(new Customer { CustomerName = "Memory Customer" }); // Filter data var filters = new List<AppFilter> { new AppFilter { FieldName = "Country", Operator = "=", FilterValue = "USA" } }; var filtered = await unitOfWork.Get(filters); // Changes are only in memory - no database operations

Event Handling

// Set up event handlers unitOfWork.PreInsert += (sender, e) => { var customer = (Customer)sender; customer.CreatedDate = DateTime.Now; customer.CreatedBy = "CurrentUser"; }; unitOfWork.PostUpdate += (sender, e) => { var customer = (Customer)sender; customer.ModifiedDate = DateTime.Now; customer.ModifiedBy = "CurrentUser"; }; unitOfWork.PreDelete += (sender, e) => { // Confirm deletion var customer = (Customer)sender; if (customer.HasOrders) { e.Cancel = true; // Prevent deletion } };

Progress Reporting

// Create progress reporter var progress = new Progress<PassedArgs>(args => { switch (args.ErrorCode) { case "END": Console.WriteLine("Commit completed"); break; default: Console.WriteLine($"Processing: {args.ParameterInt1} items"); break; } }); // Commit with progress var cancellationToken = new CancellationTokenSource().Token; var result = await unitOfWork.Commit(progress, cancellationToken);

Filtering and Searching

// Complex filtering var filters = new List<AppFilter> { new AppFilter { FieldName = "Country", Operator = "=", FilterValue = "USA" }, new AppFilter { FieldName = "CustomerType", Operator = "!=", FilterValue = "Inactive" }, new AppFilter { FieldName = "CreditLimit", Operator = ">", FilterValue = 1000 } }; var filteredCustomers = await unitOfWork.Get(filters); // Predicate-based search var customer = unitOfWork.Read(c => c.Email == "john@example.com"); // Multiple results with predicate var results = await unitOfWork.MultiRead(c => c.Country == "USA");
?? Best Practice: Always handle the PreCommit and PostCommit events to implement business rules and auditing. Use the Cancel property in Pre-events to prevent operations when business rules are violated.

Performance Considerations

  • Lazy Loading: Data is loaded on-demand from the data source
  • Change Tracking Overhead: Each entity change triggers event handlers
  • Memory Usage: Original values are preserved for undo functionality
  • Batch Operations: Commit processes all changes in a single transaction

Thread Safety

The UnitofWork is not inherently thread-safe. When accessing from multiple threads, ensure proper synchronization:

// Thread-safe access example lock (unitOfWork) { unitOfWork.Add(newEntity); await unitOfWork.Commit(); }

Memory Management

The class implements IDisposable. Always dispose properly:

using (var unitOfWork = new UnitofWork<Customer>(dmeEditor, "DB", "Customers")) { // Use unit of work } // Automatically disposed
